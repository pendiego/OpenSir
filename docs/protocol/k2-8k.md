## Profile record (1408 bytes)

One flat record, no header and no shift-profile loop. Layout from the vendor profile codec's encode/decode (`observed-static`).

| Offset | Length | Content |
|---|---|---|
| 0 | 32 | Profile name, UTF-8, trimmed |
| 32 | 32 | Fun data: motor (4), audio (5), extend (10), reserved (13) |
| 64 | 112 | 16 key blocks x 7 bytes, in the vendor key order (see `layouts/k2_8k-profile.json`) |
| 176 | 1014 | 6 function keys x 169 bytes: FL1, FR1, FL2, FR2, FL3, FR3 |
| 1190 | 64 | Triggers L2, R2: 2 x 32 bytes |
| 1254 | 72 | Sticks Left, Right: 2 x 36 bytes |
| 1326 | 82 | Motion Aim, Tilt: 2 x 41 bytes |

Total 1408, matching `EveryPacketLength`.

Key block (7 bytes): turbo (en, speed), map (en, value1..3), toggle_en.

Function key block (169 bytes): turbo (2), map (4), toggle_en (1), macro bitfield (1: bit0 enable, bit1 open, bit2 cycle enable), cycle time (2, `256*high + low`), step count (1), 32 steps (31 x 5 + 3 bytes: step data, hold high/low, delay high/low).

Trigger (32 bytes): turbo (2), dead zone (1 enable + four 2-byte big-endian values), map (4), toggle_en, quick-trigger status (bit7 enable, bit0 mode1, bit1 mode2), quick start/end values, linear module (13).

Stick (36 bytes): enable and square (2), dead module (9), linear module (13), map module (12: enable, x/y flip, axis ratio, mouse DPI, map index, cross, four directions, dead value).

Motion (41 bytes): sensor profile status (1), three quick-key values (3), active axis (1), dead module (9), linear module (13), map module (14, including z flip and stick sensitivity).

Fun data (32 bytes): motor 4 bytes (left, right, LT, RT). Audio 5 bytes (enable, volume, mixer, mic mute, mic sensitivity). Extend 10 bytes (shift enable, shift value, D-pad diagonal lock, XInput ABXY change, Switch ABXY change, report-rate gear, sensor quick mode, stick resolution, LS and RS anti-jitter). Reserved 13 bytes, unknown; decoder skips them.

## Light packet (229 bytes)

Five 44-byte animation blocks, then a raise-to-wake byte (bit 0) and an 8-byte tail: standby time, dock LED mode, dock LED brightness, report rate, 4-byte device id. Each block: 16 bytes (mode, home effect index, profile-number effect index, home phantom speed, profile-number phantom speed, the five brightness and four speed settings, phantom hue, rainbow hue), then 7 colours of 4 bytes (hue u16 big-endian, saturation, value) in zone order lower left, lower right, upper left, upper right, home, profile number, home button. `vendor-exec` (`layouts/k2_8k-light.json`, `k2_8k-raw-vectors.json`).

## Vendor app converter
The vendor app converts between its UI model and the raw record. It fills defaults on decode (for example active axis 0 becomes 2, anti-jitter 0 becomes 11), so the app's own decode-then-encode is not lossless. OpenSir works on the raw record and keeps unmodelled bytes, so its round trip is exact (opensir-core `tests/hid_family.rs`).
