# OpenSir architecture

OpenSir is an open-source configurator for GameSir controllers. It is a clean-room reimplementation built from the protocol facts in `docs/protocol/` and the screen inventory in `docs/spec/`. Controller cover images are GameSir's official artwork, stored in `static/pads/`; no vendor code or firmware is shipped.

## Layout

```
Cargo.toml                 workspace: crates/*, src-tauri
crates/opensir-core/       protocol + device layer, no Tauri dependency
  src/model.rs             serde types (camelCase JSON), shared with the UI
  src/keycodes.rs          key/button code table
  src/profile.rs           680-byte profile codec (cyclone2-profile.md)
  src/light.rs             light profile (slot 32) codec
  src/shift.rs             shift profile (slot 5) codec
  src/command.rs           command builders + inbound classifier (cyclone2-transport.md)
  src/transport.rs         hidapi: enumerate, open config collection, send queue, ack, resend
  src/device.rs            Cyclone2 session: attach sequence, read all, write diffs, heartbeat
  src/input.rs             report 0x12 gamepad-state parser
  tests/vectors.rs         golden vectors from docs/protocol/*-vectors.json
crates/opensir-cli/        `opensir list | info | dump [--json]` (read-only)
src-tauri/                 Tauri 2 shell: commands + events wrapping opensir-core
src/                       SvelteKit (adapter-static, ssr=false) UI
src/lib/types.ts           TS mirror of model.rs (generated by ts-rs from opensir-core)
src/lib/api.ts             typed wrappers over invoke()/listen(); mock backend when not in Tauri
```

## Device modes

Config works only when the controller enumerates with a config PID (C2: 0x101D wired, 0x102A wireless, 0x1053 wired ADC, 0x100B wireless ADC) on usage page 0xFFF0. Any other PID from VID 0x3537 is listed as `configCapable: false` and the UI tells the user to switch the controller to a config-capable (PC) mode. Nothing is ever sent to a non-config device.

## Tauri contract

Commands (all async, errors as `string`):

| Command | Args | Returns |
|---|---|---|
| `list_devices` | – | `DeviceInfo[]` |
| `open_device` | `id` | `DeviceSnapshot` (fw version, current profile index, profiles 1-4, shift, light, battery) |
| `close_device` | `id` | – |
| `save_profile` | `id, index, profile: Profile` | – (writes only changed byte ranges, vendor offsets/lengths) |
| `switch_profile` | `id, index` | – |
| `reset_profile` | `id, index, scope: "all" \| "mapping" \| "sticks" \| "motion" \| "triggers" \| "motors"` | `Profile` |
| `save_light` | `id, light: LightProfile` | – (Cyclone 2) |
| `save_effect_light` | `id, light: EffectLight` | – (T3CE, G7ProCE, K2_8K effect light) |
| `set_light_playback` | `id, playing, frame` | – |
| `vibrate` | `id, left, right, durationMs` | – |
| `set_test_mode` | `id, on` | – (starts/stops `gamepad-state` events) |
| `export_profile` / `import_profile` | `profile, path, model` / `path, model` | – / `Profile` (OpenSir JSON, versioned, tagged with the model id) |

Events: `device-list-changed` (`DeviceInfo[]`), `device-state` (`{id, currentProfile, battery, charging}`), `gamepad-state` (`{id, buttons: string[], lx, ly, rx, ry, lt, rt}`), `device-error` (`{id, message}`).

## Safety rules in code

- Firmware update / DFU commands are not implemented.
- Writes go through one function that validates profile index (1-4, 5 shift, 32 light) and payload length before sending.
- Encoding starts from the raw bytes read from the device, so unknown and reserved bytes are written back unchanged.
